# TLDR IT Reader

A news-style website that shows the TLDR newsletters from my Gmail inbox, so I don't have to open my email every day.

## Architecture

Fully static. There is no backend, and the website never talks to Gmail.

```
┌────────────┐    ┌─────────────────────────┐    ┌──────────────────┐    ┌──────────────┐    ┌──────────────┐
│ Gmail API  │ -> │ Python fetcher          │ -> │ data/issues.json │ -> │ Astro build  │ -> │ GitHub Pages │
│ (readonly) │    │ GitHub Actions, daily   │    │ committed to repo│    │ reads JSON at│    │ static site  │
└────────────┘    │ cron (00:00 UTC)        │    └──────────────────┘    │ build time   │    └──────────────┘
                  └─────────────────────────┘                            └──────────────┘
```

- **Credentials** (`GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`, `GMAIL_REFRESH_TOKEN`) live only in GitHub Actions Secrets.
- **Public data only:** the repo stores article titles, links, short snippets (max ~200 chars), section names and issue dates. It never stores full email bodies.

## Folder structure

```
.
├── .github/workflows/   GitHub Actions (daily fetch + deploy)      [Stage 6]
├── data/                issues.json, generated by the fetcher      [Stage 3]
├── fetcher/             Python scripts that read Gmail             [Stage 2-3]
├── site/                Astro website
│   ├── public/          Static files copied as-is (favicon, images)
│   └── src/
│       ├── pages/       Each file = one URL (file-based routing)
│       ├── layouts/     Page "shells" (shared <html>, header, footer)
│       └── components/  Reusable UI pieces (e.g. ArticleCard)
├── requirements.txt     Python dependencies
└── README.md
```

## Local setup (GitHub Codespaces)

### Python fetcher

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### Astro site

```bash
cd site
npm install
npm run dev
```
